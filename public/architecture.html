The flow

Quality checks

Evals 1: test cases

Before release. 15 known cases with correct answers, run after any AI change (model, prompt, prices) to check the AI still gives the right answer. Safety gate: a damaged scooter is never billed at the counter.

Evals 2: human vs AI production

Once live. Every month, a sample of real returns is checked fully by hand, without seeing the AI's answer, and compared with the AI. Every mismatch becomes a new test case.

Rule checker

Checks every agent answer. 4 rules:

  • The answer is in the exact expected format.
  • Prices come only from the parts catalog, never from an agent.
  • A scratch is always priced as a polish, never as a new panel.
  • An agent's note to a rider or inspector never contains a rupee amount.

If an answer breaks a rule: one retry, then it goes to the Inspector.

Unit tests

90 automatic tests check the Router and the rule checker on every code change.

Step by step

  1. At pickup, the Detector records the scooter and its 4 pickup photos.

    Branch, registration number, model, colour and rider, then front, rear, left and right photos. Renting the scooter out happens in another system; this records the "before" state.

  2. When it comes back, the Detector picks the returned scooter.

    From the active rentals list, where it has been since its pickup was recorded.

  3. The Detector uploads 4 return photos.

    Front, rear, left and right.

  4. The Detector assesses the damage.

    One click starts the two agents below.

  5. Damage Agent (AI) finds new damage in the photos.

    It compares each return photo with the matching pickup photo and lists only damage that is new.

  6. Estimate Agent (AI) estimates the cost from the parts catalog.

    It picks a repair part for each damage item; the price always comes from the catalog.

  7. The Router decides Path A or Path B.

    It uses fixed rules and is not an agent. Path A, back to the Detector, when the cost is ₹1,500 or less and both agents are confident. Path B, forward to the Inspector, when the cost is over ₹1,500, an agent is unsure, the photos are too poor to judge, there is a crack or broken part, the Detector escalated, or an agent failed the rule checks twice.

  8. Path A: Bill Agent (AI) writes the rider's note, the Detector confirms the bill, and the rider pays.

    The amount is taken from the deposit. The payment itself happens outside the app.

  9. Path B: Order Agent (AI) writes the work order, and the Inspector reviews it.

    The Inspector approves or changes each line (adding any missed part with its side), then confirms. Or sends it back with a reason: the Detector re-checks the saved photos, replaces any, and runs the assessment again.

  10. Path B: The Detector gets a notification and settles the final amount.

    The Detector collects the extra amount or refunds the rest of the deposit.

  11. The dashboard shows the fleet's damage history.

    Each scooter's damage by side, type, date and final amount, plus the Path A/B split, money recovered and returns per Bangalore branch.

Next steps for a production version

Fine-tune the Damage Agent

Train it on 1,000+ real damage photos, so it recognises scratches, dents and cracks on these scooters more reliably.

Add a second Damage Agent as a judge

Train a second, independent agent that checks the first one's answer. When they agree, the answer is more reliable; when they disagree, the return goes to the Inspector.

Log every rule-check failure

Save each answer the rule checker rejects and the rule it broke, to see which rule fires most and where the AI is weakest.
